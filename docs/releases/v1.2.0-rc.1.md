# WhatsApp Electron v1.2.0-rc.1 — First Linux preview

This is the first public prerelease of the unofficial Linux wrapper. It is not
an official WhatsApp or Meta application and it is not a stable release.

## Verified in the release pipeline

- Source is tagged `v1.2.0-rc.1` from the final verified `main` commit.
- Node 22/24 static checks and the repository's 62 automated tests pass.
- Linux x86_64 DEB and AppImage builds are produced by the controlled workflow.
- Release assets include matching source, `BUILD-COMMIT.txt` and `SHA256SUMS`.
- Electron sandboxing, context isolation, web security, navigation restrictions
  and fail-closed media permission policies are retained.
- Screen sharing is intentionally blocked because Electron 43.7.0 does not
  provide a separately verifiable safe boundary for all capture request paths.

## Not verified by this prerelease

The following require a consenting account, physical devices and supervised
manual testing. They must not be inferred from a successful page load or a call
button:

- QR login and account linking
- Session restoration after restart and upgrade
- Chat send/receive and image/document attachments
- Notifications, tray visibility and autostart on each desktop
- Incoming/outgoing voice and video calls
- Ten-minute background/minimized calls
- Native versus compatibility browser identity behavior
- Ubuntu/Mint, GNOME/KDE, Wayland/X11 and Intel/AMD/NVIDIA coverage

See [calling validation](../calling-validation.md) for the complete matrix.
Rows without real evidence are `NOT RUN`; screen-sharing rows are `BLOCKED`.

## Installation

Use the DEB on Debian/Ubuntu systems or the AppImage on a compatible Linux
desktop. Verify `SHA256SUMS` before installation. Do not use `--no-sandbox`.
Preserve the existing WhatsApp profile and do not delete it as a troubleshooting
step.

## Reporting issues

Use the [bug report template](https://github.com/UdayaSri0/whatsapp-electron-main/issues/new?template=bug_report.yml)
and include sanitized Help → Copy Diagnostics output. Never attach QR codes,
messages, contacts, media, cookies, access tokens or full profiles.
